# Unified System Model (USM)

**A unified approach to documenting software systems for humans and AI agents.**

The **Unified System Model (USM)** is an information model for describing software systems consistently, separating **what exists today** from **what has been designed** and **what is being explored**.

USM organizes knowledge along two independent dimensions:

### Abstraction Layers

- **Product** — What the system must accomplish: capabilities, behaviors, and requirements.
- **System Design** — How the system is conceptually organized: domain models, responsibilities, and logical architecture.
- **Technical Design** — How the system is concretely realized: technologies, interfaces, modules, and code-level design.

### Knowledge States

- **Reality** — What currently exists.
- **Commitment** — What has been accepted as the intended design.
- **Exploration** — What alternatives are being considered.

### Core Principles

- **One system, one model.** All documentation describes the same underlying system.
- **Concept-oriented.** Pages describe meaningful subjects at any level of granularity.
- **Explicit states.** Reality and Commitment coexist without being confused.
- **Connected knowledge.** Concepts are linked across abstraction layers.
- **Progressive discovery.** A single entrypoint enables navigation from system overview to implementation details.

USM is inspired by Domain-Driven Design, Clean Architecture, and Spec-Driven Development, but remains methodology- and technology-independent.
